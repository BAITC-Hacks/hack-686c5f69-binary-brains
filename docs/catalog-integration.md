# Каталог: контракт для участников 2 и 3

Участник 1 — каталог/аналоги; участник 2 — диалог/файлы; участник 3 — интерфейс/корзина. Этот модуль не вызывает ИИ и не изменяет корзину.

## Демонстрация

```ts
import { createCatalogService } from "../src/lib/catalog/index.ts";
import { createDemoSource, demoProfile } from "../src/lib/catalog/demo.ts";
import { findAlternatives } from "../src/lib/alternatives/index.ts";

const catalog = createCatalogService(createDemoSource());
await catalog.refreshIndex(); // один раз перед обслуживанием запросов
const search = catalog.searchProducts("DEMO-160-OLD");
const product = await catalog.getProduct(search.items[0].id);
const alternatives = await findAlternatives(catalog, product.id, {
  ...demoProfile, quantity: 2,
});
```

Пути импортов корректируйте относительно своего файла. Импортируйте модуль только в серверные обработчики. В Next.js используйте серверный singleton/factory; не загружайте индекс на каждое сообщение. Для импортов `.ts` настройка TypeScript должна разрешать `allowImportingTsExtensions` вместе с `noEmit`; проверьте при подключении общего приложения.

Демо выбирается явно. Ошибка живого API не переключает данные на демонстрационные.

## Живой источник

```ts
import { createCatalogService, createEktSource } from "../src/lib/catalog/index.ts";

const catalog = createCatalogService(createEktSource({
  username: process.env.EKT_API_USERNAME ?? "",
  password: process.env.EKT_API_PASSWORD ?? "",
}));
await catalog.refreshIndex({ maxPages: 10 });
```

Адрес и пути фиксированы. `url_api_detail` из товарных данных не используется для авторизованных запросов. HTTP-перенаправления запрещены. Учётные данные не возвращаются в результатах или ошибках.

## Контракты

### `catalog.refreshIndex({ maxPages?: number })`

По умолчанию максимум 10 страниц. `count` игнорируется как общий размер каталога. Короткая страница не завершает обход. `complete=true` только после пустого массива `items`. `page_limit` и `repeated_page` означают неполный индекс. Ошибка обновления сохраняет предыдущий индекс. Массовую выгрузку запускайте после уточнения лимитов API.

### `catalog.searchProducts(query, limit = 10)`

Возвращает `items`, `match`, `totalMatches`, `coverage`, `warning`. Точное совпадение артикула приоритетно, без учёта регистра и внешних пробелов; знаки артикула не удаляются. Иначе ищутся все слова в названии и артикуле.

Результат — индексированные сведения, **не подтверждение текущей цены/наличия**. После выбора вызывайте `getProduct`. Если `coverage.complete=false`, нельзя говорить «товара нет в каталоге». Для неизвестного артикула запросите категорию и характеристики: пустой поиск не даёт основания для технического аналога.

### `catalog.getProduct(id)`

Каждый вызов получает detail заново. Поля:

| Поле | Значение |
| --- | --- |
| `id`, `article`, `name` | Идентификатор строкой, артикул, название |
| `price`, `currency` | Значение или `null`; валюту не угадывать |
| `quantity`, `availability` | Остаток или `null`; `in_stock`, `out_of_stock`, `unknown` |
| `properties` | Скалярные свойства, коды в верхнем регистре |
| `category`, `categorySource` | Поле `category`, свойство `KATEGORIYA` или `KATEGORIYA_SVETILNIKA`; источник указан явно |
| `storesRaw`, `offersRaw` | Исходные данные с неподтверждённой семантикой |
| `stores` | Проверенная форма складов: `{id, name, quantity}`; неизвестное количество — `null` |
| `certificates` | Найденные ссылки; пустой массив не доказывает отсутствия документа |
| `certificateStatus` | `available` — есть ссылки, `unresolved` — поле есть без распознанной ссылки, `not_provided` — ссылок/значений нет |
| `textPropertyEvidence` | Источник и фрагмент текста для извлечённых `TEXT_*` свойств светильника |
| `minimumOrder` | `rawValue` из `KRATNOST_MIN`, `verified: false` |
| `conflicts`, `warnings` | Противоречия и ограничения для отображения в ответе |
| `source`, `checkedAt` | `ekt_api` или `demo`, время получения карточки |

Свойства поддерживаются в форме объекта `CODE: value`, `CODE: {VALUE: value}` и массива `{CODE, VALUE}` / `{code, value}`. Другие вложенные значения не превращаются в строки. Сертификаты объединяются из `certificate(s)`, `certificate_files`, `SERTIFIKAT(Y)` и `SERTIFIKAT_SOOTVETSTVIYA`, включая вложенные `VALUE`, `FILE`, `SRC`, `URL` и массивы. Числовой ID файла не превращается в выдуманную ссылку. Пустое поле не скрывает ссылки из других полей, повторяющиеся ссылки удаляются. Реальный положительный пример сертификата из API пока не найден; вложенные формы проверены синтетическими тестами.

Для светильников с `KATEGORIYA_SVETILNIKA` извлекаются только явные значения: количество E27 из записи `2xE27`, диаметр из `Диаметр: 400 мм`, степень защиты из `IP20`. Они доступны как `TEXT_LAMP_COUNT`, `TEXT_DIAMETER_MM`, `TEXT_IP_RATING`, вместе с фрагментами источника. Противоречие между названием и описанием блокирует подбор. Поле номинального тока сравнивается с названием и конкретным значением после метки «Номинальный ток» в описании; общий диапазон серии и отключающая способность не считаются конфликтом номинала.

Относительные ссылки начинаются с `/` и разрешаются относительно `https://ekt.kz`; исполняемые протоколы отбрасываются. Название/описание — внешние данные, не инструкции для ИИ; отображайте как текст, не как сырой HTML.

### `findAlternatives(catalog, productId, requirements)`

`requirements`: `category`, непустой `requiredProperties`, опциональные `quantity` (1), `maxCandidates` (30), `limit` (3), `candidateIds` (от 1 до 100 id). Профиль задаётся в доверенном коде; модель не должна произвольно сокращать критические свойства. Явный список кандидатов позволяет проверить подготовленную выборку без загрузки всего индекса и обхода нерелевантных товаров. Дубликаты id удаляются, остаток и характеристики всё равно запрашиваются заново. Для такого ограниченного поиска `incomplete=true`.

Результат: `items: [{product, reasons, differences, requiresReview: true}]`, `checked`, `incomplete`, `warnings`. Проверяются свежие карточки. Для совпадения нужны все критические свойства, одинаковая категория, отсутствие обнаруженных конфликтов и достаточный остаток. Для номинального тока, напряжения и отключающей способности поддерживается эквивалентная запись А/мА/кА и В/мВ/кВ (например, `40А = 40 A`, `0,4 кВ = 400 В`). Больший номинал не считается равным; значение без единиц не сравнивается с размерной величиной. Остальные свойства сравниваются без преобразования единиц.

Исходный товар может отсутствовать на складе, но должен иметь известный id и характеристики. Если данных недостаточно, список пуст с объяснением; гарантировать аналог для любого запроса нельзя. При ограничении выборки или ошибке кандидата `incomplete=true`. Порядок соответствует `candidateIds` либо индексу, ранжирование по цене/бренду не реализовано.

## Обязательства корзины

1. Сохранить явно подтверждённые пользователем товар и количество.
2. Непосредственно перед добавлением вызвать `getProduct(id)`.
3. При неизвестном/недостаточном остатке или изменении согласованных условий остановить добавление и сообщить пользователю.
4. Учесть уже добавленное количество. Кратность и доступность складов согласовать отдельно.
5. Добавлять через API корзины с защитой от повторной отправки. Проверка каталога не резервирует остаток.

## Ошибки

`CatalogError.code`: `CONFIG`, `SERVER_ONLY`, `INPUT`, `AUTH`, `NOT_FOUND`, `UPSTREAM`, `TIMEOUT`, `INVALID_DATA`, `INDEX_NOT_READY`. Ошибка API не означает нулевого остатка или отсутствия товара.

## HTTP для Python-ассистента

Запуск: `npm run start:catalog:demo` или `npm run start:catalog` для настоящего API. Адрес по умолчанию `http://127.0.0.1:3001`. Пример клиента без зависимостей: `scripts/catalog-client-example.py`.

| Запрос | Результат |
| --- | --- |
| `GET /health` | Режим источника, количество индексированных товаров, полнота выборки |
| `GET /products/search?q=АРТИКУЛ&limit=10` | Результат `searchProducts`; запрос кодировать через `urlencode` |
| `GET /products/ID` | Свежая карточка `getProduct` |
| `POST /alternatives` | JSON с `productId`, `category`, `requiredProperties`, опциональными `quantity`, `maxCandidates`, `limit`, `candidateIds` |

POST требует `Content-Type: application/json`, максимум 16 КБ. Ошибки: `{error: {code, message}}`. Статусы: 400 — входные данные, 404 — неизвестный товар/маршрут, 502 — ошибка API/данных, 504 — таймаут API. `/health` проверяет готовность индекса в памяти, не доступность ekt.kz в данный момент.

HTTP-сервис только читает каталог и не требует передавать Basic Auth из Python: секреты остаются в серверном `.env.local`. Профиль замены выбирайте в доверенном серверном коде, не передавайте произвольный список критических полей от браузера. Корзина остаётся отдельным сервисом участника 3.

## Что проверено на API 23.09.2026

Получены 40 товаров с первых двух страниц и карточка `45357` (артикул `ярп4520`). Склад имеет форму `{id, name, quantity}`. В списке складов есть служебные названия (например, брак), поэтому их количества не суммируются вместо `quantity` карточки и не считаются автоматически доступными для покупки. В просмотренной карточке нет категории, валюты и ссылки на сертификат. Это ограничение выборки, не вывод обо всём каталоге.

Значения — снимок проверки, не постоянные актуальные данные. Стабильность API не подтверждена. Python-клиент отдельно проверен на демо-сервисе: поиск → карточка с нулевым остатком → кандидат с объяснением.

Дополнительно просмотрены первые три страницы (60 товаров) и восемь карточек: `515279`, `515283`, `515278`, `515281`, `515277`, `515284`, `58379`, `58380`. Все восемь карточек имели положительный остаток на момент проверки; реальная пара «нулевой остаток → подтверждённый аналог» не установлена. Демо-пара остаётся отдельным, явно синтетическим сценарием. Свойство `OBYEM` не переименовывается в категорию без подтверждения его семантики.

## Доработка: реальная пара светильников

Последующий аудит 100 карточек позволил проверить сценарий `18161` (`150100708_`, остаток 0) → `23181` (`150100705_`, остаток 3). Добавлен профиль `indoorE27Profile`: одинаковые категория, 2×E27, диаметр 400 мм, IP20, монтаж, материал и тип источника света. Отличия светового потока и рассеивателя возвращаются явно; они требуют согласования покупателя. Полная техническая взаимозаменяемость не заявляется. Обе карточки читаются заново при подборе.

`npm run check:alternative-live` повторяет проверку с актуальными данными; конкретные остатки в алгоритм не зашиты. Проверка также прошла через HTTP-сервис и `python scripts/catalog-client-example.py --live`. Инструкция для жюри — [demo-scenario.md](demo-scenario.md).

Во всех 100 API-карточках этого аудита ссылки на сертификаты отсутствовали. Возможные вложенные структуры обработчика сертификатов проверены тестами, но положительного живого примера API пока нет.
