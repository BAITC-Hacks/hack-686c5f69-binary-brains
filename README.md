# HackAlem AI — ассистент ekt.kz

Команда binary brains, кейс №1. Ассистент для частных покупателей и закупщиков электротехнических товаров: поиск и консультация → выбор → подтверждение → корзина.

## Текущее состояние

Реализованы серверный каталог и подбор кандидатов участника 1, чат и обработчики участника 2, а также адаптивный интерфейс и демонстрационная корзина участника 3. Ассистент пока использует собственный поисковый клиент; сервер корзины проверяет актуальный остаток через сервис каталога участника 1 при настройке EKT API.

- Точный поиск артикула и поиск по словам в названии в загруженной выборке.
- Адаптер API ekt.kz с Basic Auth, таймаутом и безопасными сообщениями об ошибках.
- Свежая детальная карточка: цена, наличие, свойства, ссылки на сертификаты в поддерживаемых полях.
- Исходные данные складов без предположений об их доступности покупателю.
- Обнаружение противоречия номинального тока между названием/описанием и свойствами.
- Подбор по заданной категории и критическим характеристикам, проверка остатка, объяснение совпадений и различий.
- Категория из `KATEGORIYA` с указанием источника; сравнение эквивалентных записей единиц тока и напряжения.
- Явное обозначение неполноты каталога и демонстрационных данных.

**Живой API проверен 23.09.2026:** исследованы первые 100 карточек, проверены поиск артикула, склады, категории и конфликт 160 А / 250 А. Найдена реальная пара светильников: недоступный KAMELYA MAXI (`150100708_`) → доступный кандидат AKASYA MAXI (`150100705_`). Подбор показывает совпадения и отличия светового потока/рассеивателя; это кандидат на согласование, не гарантированная замена. Остатки проверяются заново.

В 100 просмотренных карточках не обнаружено ссылок на сертификаты. Парсер объединяет поддерживаемые поля и отличает отсутствие ссылки от неразобранного значения. Соединение нестабильно: отдельные запросы завершаются таймаутом. Валюта и правила технической замены ещё требуют уточнения. Синтетическое демо отделено от живого API.

## Запуск и проверка

Нужен Node.js 24.12 или новее. Рабочий сервис не использует сторонних библиотек; для разработки добавлены TypeScript и типы Node.js. Установка из lock-файла и проверки:

```sh
npm ci
npm run typecheck:catalog
npm test
npm run demo:catalog
```

`npm run typecheck:catalog` проверяет автономный блок каталога, его скрипты и тесты. Приложение запускается командами `npm run dev` и `npm run build`; чат доступен на `http://localhost:3000`. Общую проверку типов выполняет `npm run typecheck`.

Тесты включают регрессии на небольших снимках настоящих API-ответов из `tests/fixtures/ekt-sample.json`. Снимки не используются сервером для выдачи актуальных цен или остатков.

Демо показывает товар без остатка `DEMO-160-OLD`, доступного кандидата `DEMO-160-NEW` и конфликт `DEMO-CONFLICT`.

Для проверки API скопируйте `.env.example` в `.env.local`, заполните серверные `EKT_API_USERNAME` и `EKT_API_PASSWORD`, затем:

```sh
npm run check:catalog-live
```

Для конкретной карточки: `npm run check:catalog-live -- --id=515291`.

Реальная пара аналогов с новой проверкой остатков:

```sh
npm run check:alternative-live
```

Команда ищет кандидата среди первых 100 товаров без заранее заданного id замены. При проверке исходный остаток был 0, кандидат — 3 шт.; эти значения не зашиты в алгоритм. Вывод содержит совпадение 2×E27, диаметра 400 мм, IP20 и монтажа, а также отличия: 1465 → 1152 лм, призматический → опаловый рассеиватель. Покупатель должен согласовать отличия. Если данные изменятся, команда сообщает, что сценарий больше не выполняется. Для адресной диагностики предусмотрен флаг `--targeted`.

`check:catalog-live` читает только первые две страницы и одну детальную карточку. Выборка помечается как неполная. `.env.local` исключён из Git. Не добавляйте префикс `NEXT_PUBLIC_` к секретам и не передавайте их в клиентские компоненты.

## Подключение Python-ассистента

Текущий ассистент участника 2 написан на TypeScript в `src/lib/assistant/`; старый Python-каркас также сохранён. Для Python и других серверных клиентов доступен HTTP-сервис каталога на `127.0.0.1:3001`:

```sh
npm run start:catalog:demo
# В другом терминале:
python scripts/catalog-client-example.py
```

Живой режим: `npm run start:catalog`, затем в другом терминале `python scripts/catalog-client-example.py --live`. Режимы выбираются явно; таймаут не переключает сервис на выдуманные остатки. Сервис предназначен для вызовов сервером ассистента на той же машине; не публикуйте этот внутренний порт напрямую. Настройки: `CATALOG_PORT` (3001), `CATALOG_MAX_PAGES` (5 для API, 3 для демо).

Для локального исследования API есть `npm run audit:catalog -- --page=1 --pages=2 --details=20`. Снимки попадают в исключённую из Git `.local/catalog-audit/`; повторный аудит может читать ранее сохранённые карточки, поэтому для проверки свежего остатка используйте `getProduct` или команды `check:*`.

## Данные и ограничения

API: `https://ekt.kz/api/products?page=N` и `https://ekt.kz/api/products/detail?id=ID`. Схема взята из сохранённого контекста кейса; исчерпывающий контракт не предоставлен. `count` не считается общим размером каталога. Индекс ограничен числом страниц и считается полным только после пустой страницы; повтор страницы останавливает загрузку с отметкой о неполноте.

Валюта не предполагается. Неизвестные цена/остаток представлены `null`. Отсутствие ссылки на сертификат не доказывает отсутствия документа. `KRATNOST_MIN` передаётся как неподтверждённое значение. Склады и `offers` требуют уточнения схемы и бизнес-правил.

Категория и профиль критических характеристик должны быть подтверждены до живого подбора аналогов. `RECOMMEND` не доказывает взаимозаменяемость. Совпадения по профилю — кандидаты для проверки специалистом, не гарантия технической замены. Демо-профиль не является утверждённым инженерным справочником.

Индекс живёт в памяти одного процесса; после перезапуска требуется загрузка. Детали запрашиваются заново, но остаток может измениться после ответа: корзина обязана перепроверять его непосредственно перед добавлением. Перед проверкой карточек кандидаты ранжируются по сходству названий; сходство не считается доказательством замены. Последовательная проверка имеет общий лимит времени 4 секунды и останавливается при наборе нужного количества результатов. При истечении времени или неполной выборке возвращается `incomplete=true`. Для production потребуются фоновое обновление индекса и проверенные лимиты API.

Deployment отсутствует. API корзины и интеграция с сессией покупателя не предоставлены. Ключи и платёжные данные модуль не сохраняет.

## Участник 2: ИИ-ассистент и обработка файлов

Зона ответственности:

- логика диалога в чате;
- хранение контекста сессии;
- вызов инструментов каталога: `searchProducts`, `getProduct`, `findAlternatives`;
- ответы про оплату, доставку и минимальную партию;
- извлечение позиций из JPEG, Excel, Word и PDF;
- уточняющие вопросы при неоднозначном запросе;
- подготовка ответа для интерфейса: текст, карточки товаров, ссылка на корзину после подтверждения.

### API

`POST /api/chat`

```json
{
  "sessionId": "optional-session-id",
  "message": "Есть ли автомат 16А?"
}
```

Ответ:

```json
{
  "sessionId": "session-id",
  "message": "Текст ответа ассистента",
  "cards": [],
  "needsConfirmation": true
}
```

`POST /api/upload`

`multipart/form-data`:

- `file` - JPEG, Excel, Word или PDF;
- `sessionId` - необязательный id сессии.

Ответ:

```json
{
  "sessionId": "session-id",
  "fileName": "specification.pdf",
  "items": []
}
```

### Интеграция с каталогом

В `src/lib/assistant/catalogClient.ts` пока используется собственный клиент: живой при наличии его переменных окружения, иначе демонстрационный. Блок участника 1 уже доступен в `src/lib/catalog/` и `src/lib/alternatives/`, но ещё не подключён к ассистенту. При интеграции нужно согласовать форматы данных и методы:

- `searchProducts(query)`
- `getProduct(id)`
- `findAlternatives(productId, requirements)`

Данные доступа к API ekt.kz нельзя хранить в коде. Используйте переменные окружения:

```bash
EKT_API_BASE_URL=https://ekt.kz/api
EKT_API_USER=...
EKT_API_PASSWORD=...
EKT_API_SEARCH_PAGES=3
```

Локально создайте `.env.local` по примеру `.env.example`. Файл `.env.local` исключен из Git, поэтому реальные учетные данные не попадут в коммит.

Сервис участника 1 читает логин из `EKT_API_USERNAME`, текущий клиент участника 2 — из `EKT_API_USER`. До объединения клиентов при их совместном запуске оба поля должны содержать одинаковый логин; пароль общий.

Если переменные окружения заполнены, ассистент использует серверный Basic Auth клиент к ekt.kz:

- `GET /products` - первая страница каталога;
- `GET /products?page=2` - следующие страницы;
- `GET /products/detail?id=515291` - детальная карточка товара.

Если переменные окружения не заполнены, включается демонстрационный каталог.

### Ограничения демо

- Корзина демонстрационная и не меняет корзину сайта ekt.kz. Веб-интерфейс и публичный `/api/chat` при явном подтверждении записывают позиции в серверное хранилище демо-корзины и дают ссылку `/cart`.
- PDF/JPEG распознавание подготовлено как адаптеры. Для полноценного демо нужно подключить OCR и библиотеку чтения PDF.
- Ассистент не добавляет товар в корзину без явного подтверждения пользователя.
- Ассистент не принимает и не хранит платежные данные.
